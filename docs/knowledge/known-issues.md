# Known issues — accepted problems the team must not "fix" unasked

Problems here are **known and deliberately not being fixed in the current task**. They are recorded so
that agents stop rediscovering them, stop reporting them as new findings, and stop fixing them as
scope creep.

Each entry records *why* it is accepted. An accepted issue without a stated reason is
indistinguishable from an oversight.

> **Status: template.** Replace the placeholder rows with this project's accepted issues. An empty
> table is the correct initial state for a new project — the rows below are shapes to copy, not
> content to keep.

## How to use this file

- **Reference, do not fix.** If you encounter a known issue while working on something else, note it in
  your report as a known issue and move on. Fixing it is a separate task.
- **Do not suppress reporting entirely.** If a known issue makes your task's acceptance criteria
  unverifiable, that is a new finding and must be raised.
- **Removing an entry is an explicit decision**, not a cleanup. Say what changed.
- **Framework-level issues do not belong here.** This file is copied into product repositories, so a
  defect of the framework recorded here would ship into a new project and read as a defect of that
  project. Those live in the framework's own `.agent/framework-known-issues.md`.
